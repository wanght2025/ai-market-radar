- 核心用户是独立做盘后研究、盘前复核的个人 A 股投资者，具备基本行情知识，但不应被要求理解内部数据结构、模型缓存和请求预算代码。

## 2. 应当保留的体验优势

1. **研究事实可以追溯。** 行情、规则、AI、公告样本和原始报告都有阅读路径。股票与板块间的连接实用。
2. **数据边界比较诚实。** 非实时、有限公告样本、后补主营、分类不能直接映射、成交额不等于净流入、0 个前瞻样本都有说明。
3. **不以一个总分压倒所有信息。** 首页已经把趋势、广度、成交额放回事实层。这比未经验证的“65 分即可以买”更适合研究工具定位。
4. **基本交互可用。** 中文搜索、组合筛选、表格排序状态、详情、证据栏和历史报告均能访问；手机证据栏焦点返回正常。
5. **专业风格方向合理。** 浅色、克制配色、数字对齐和表格适合桌面研究，无需重新做大卡片或增加装饰图。

后续修改必须保留原预测不可改写、历史再研究不计前瞻、缺失不填零、来源冲突不择一填满的约束。

### R17：新AI说反事实，程序校验未阻止发布

**复现：**实际运行当前研究，额外1次模型请求成功后，进入医药生物详情。新AI写“医药指数反弹强劲且广度84%，但收盘未站上20日线，仍属等待确认”。页面标记本次生成时间05:57:32，无旧证据资格提示；保存结果的业务状态为PASSED。

**事实核对：**读取该日医药行业161条保存日线，沿用产品 `decision.trend()` 计算，得到下列结果；当前机会证据也显示“指数跌破信号日20日均线：未满足”。

| 同一行情日期2026-09-30 | 数值／判断 |
|---|---|
| 医药行业收盘 | 7,989.13点 |
| 20日均线 | 7,753.4605点 |
| 收盘减均线 | +235.6695点，约高3.04% |
| 实际上下关系 | 收盘高于20日均线 |
| AI陈述 | 收盘未站上20日线——与保存事实相反 |

**影响：**“当前研究可用”会让用户以为基本事实已核对。未来是否持续站稳属于待验证判断；本日是否高于均线是已经可以计算的事实，两者不能混为一谈。没有实际交易损失记录，但这是直接破坏核心研究可信度的问题。

**原因边界：**实际模型输入将 `history:industry:801150` 压缩为 `opportunity:801150` 的别名；机会事实包含正的参考差值和20日均线参考，却未直接提供收盘、MA20及高于MA20布尔值。原规则仍为“等待确认”，机会v1.1的四项确认条件全部满足。这使规则状态、条件定义和事实之间更易被混淆，是合理的原因推断，不能断言已证明模型内部误判机制。`decision.py:178` 的 `validate_ai()` 校验日期、结构、候选范围和引用存在性，没有验证这类均线关系陈述；引用合法不等于引用支持结论。

**最小修改：**

1. 模型输入显式保留目标日期、close、MA5、MA20及above_ma5/above_ma20；每个别名有唯一可解析的完整事实，避免模型从“等待确认”推导价格关系。
2. 把这些可计算关系作为程序生成的事实行展示；AI解释未来持续性、风险与替代解释，规则资格继续单独保留。
3. 对均线关系等少数关键事实要求结构化陈述并逐项校验，防止相反关系进入“当前合格研究”；保留失败记录，页面说明具体不一致并继续提供事实与规则。不要为一个案例引入庞大通用自然语言判真系统。
4. 将本次错误原文和输入作为隔离回归样本；不要静默改写历史AI，也不要为了迎合模型去改变原规则。

**验收：**本案例不能再被判为事实一致；均线上方／下方／恰好相等／历史不足分别有测试；“等待确认但已在MA20上方”必须合法表达。验证失败不能标READY或伪装成缓存成功，不自动新增付费重试；规则与原正式报告保持原样。界面把“结构和引用通过”与“关键事实一致”分别说明，仍不宣称预测已验证。

### R01：详情与证据引用不同版本

**复现：**个股研究 → 药明康德 → “已有证据与待办”显示“主营资料已取得 · 2026-10-07”；点击“药明康德 · 已有资料与具体核验事项”，证据栏显示“资料日期与口径 2026-10-06”。重新加载后仍存在，且两处都称为后补资料。

此项在本次真实更新前、当前资料已变化而AI仍引用旧证据时复现。完成新研究后，特定冲突可能随重新绑定暂时消失；验收必须覆盖下一次证据变化场景，不能用刚刚全部重研后的正常截图代替修复。

**影响：**用户点击证据是为了核对当前描述，却看到另一日期。即使主营内容没有实质变化，这种不一致也会削弱整套可追溯机制。

**修改：**详情、待办和对应证据入口使用同一份当前研究证据对象；旧 AI 引用的证据以明确的“当时研究证据”入口保留。区分资料发布时间、采集时间和业务适用日期；不要用一个日期替代三者。

**代码依据：**`dashboard.py` 的 `research_analysis()` 在约 135–138 行把保存研究证据加入目录，随后约 143 行更新 `research_evidence` 为当前快照，却未在这一位置同步重建各股票 `research:<code>` 目录。`dashboard-visuals.js` 的 `evidenceTasks()` 阅读当前对象，证据栏从目录读取。此顺序与实测吻合，是高度可信的原因；修改前仍应写失败复现测试。

**验收：**同一代码的当前详情、待办、证据栏在日期、正文和公告资格上逐项一致；历史 AI 可以查看其原证据，但必须带版本与截止时点。单纯采集时间变化可更新显示，不能无理由触发付费重研或让研究失效。

### R16：真实子进程输出编码与读取编码不一致

**实测：**用户进一步授权 API 深度体验后，通过页面启动真实“当前研究”更新。采集已到 `[9/36] candidate_notices`，页面阶段文字显示乱码，进度仍为已完成 0/4。更新中原研究仍可读，重复更新入口锁定，这两点正常。

## 4. 推荐的默认阅读结构与文案

目标是从“每个模块解释自己没有什么”，调整为“用户知道当前能确认什么，以及下一步做什么”。下列是产品文案方案，不是新行情结论或新交易规则。

| 层次 | 默认信息 | 示例表达 |
|---|---|---|
| 时点 | 行情基准＋资料截止＋研究资格 | “9/30 收盘行情；补充资料截至 10/7 04:11；上次 AI 部分依据已变化” |
| 市场 | 状态＋最多三项证据 | “分化：三个指数低于 MA20，上涨股约46%，等权略跌” |
| 研究边界 | 最大障碍＋可完成动作 | “行情可以阅读；AI 解释待更新。今日新模型请求次数已用尽，可核对现有资料” |
| 方向 | 最多三个方向，各一句依据和一项反证 | “医药生物：本日诊断条件满足，后续延续仍待核验；查看确认与失效条件” |
| 自选 | 用户关注对象的状态与研究范围 | “2只已保存行情；2只未进入独立研究，先核对板块与公司资料” |
| 下一次观察 | 对象＋条件＋核验时点 | “下次收盘后复核已保存板块条件，不把本日满足当作后续已兑现” |
| 深读 | 资金、事件、个股、历史与原规则 | 保持现有表格、证据栏和完整存档 |

三个维度应分开：**事实新鲜度、意见适用资格、原规则参与条件。**不要把研究未更新说成行情不可用，也不要把某板块诊断条件满足说成个股可买；资格合格也不能替代关键事实核对。

建议的状态表达仅覆盖已有业务，不增加新的状态系统：

- 有当前合格研究：直接展示意见、证据与反证。
- 合格缓存可复用：显示真实生成时点与证据截止，不把读取时间写成生成时间。
- 部分依据变化：默认展示变化涉及什么，旧意见进入明确历史入口。
- 无当前合格 AI：保留规则与事实，给具体原因及恢复路径。
- 预算或 Key 阻止生成：说明可做的数据更新与不能得到的新研究。

## 5. 实施顺序与验收方式

### 第一批：先关闭阅读可信度和导航问题

范围：R17、R01、R02、R04；约 2.5–4.5 人日。

1. 先用本次医药响应建立R17失败样本，补明确事实输入与关键关系校验，离线验证相反结论无法成为当前合格研究。

**交付标准：**关键均线事实相反的AI不能成为当前合格研究；不能再出现同一当前事实两种日期、旧 AI 被默认当当前、核验入口落到变化空页。离线回归不新增API支出。

### 第二批：让“更新”可预期、研究动作可执行

范围：R03、R05、R06、R07、R14、R15、R16；约 3–5.5 人日。

1. 先定义入口上展示的范围、缓存、预算、结果位置；复用后端判断，不由前端猜测业务资格。
2. 保留原规则，统一机会诊断与参与门槛文案；补充下一日观察。
3. 记录自动任务的最近尝试和最近合格结果，区分休市、配置与失败。
4. 用拦截模型请求或模拟数据验证用尽预算、无 Key、缓存命中、来源变化、失败保留；测试不触发付费调用。

**交付标准：**用户在启动前知道本次能得到什么，失败后知道下一步；更新成功必须分别报告行情、资料和 AI 的真实结果，不能一个“完成”覆盖所有状态。

### 第三批：提高日常查阅效率

范围：R08、R09 的最小改法、R10、R11、R12、R13；约 3–5 人日。

1. 移除默认空指标列，压缩重复信息，保留证据入口。
2. 优化手机关键状态与列表比较，补概念／资金搜索。
3. 修正来源频道与具体条目的命名，合并主题展示但保留原样本。
4. 四宽度重复真实路径；检查文字缩放、键盘和触摸目标。

**交付标准：**重点更早出现，用户更少滚动和横向拖动；信息来源、关键限制和原始记录依旧可见。

自选进入独立 AI 研究不纳入上述最小范围，应在现有预算、研究对象上限和输入规模核清后另排。优先避免新增数据源、重做评分体系、引入新组件框架等扩大范围的工作。
